# 팩트너 공개 전 체크리스트

**2026-11-03 기준** · 실제 회원가입 접수는 닫혀 있다. 운영 상호·문의 이메일·정식 문서는 미확정이다. 초안 사이트의 테스트 가입은 실제 자료 대신 임시 계정을 사용한다. 아래 항목은 공개 직전에 다시 확인한다.

## 1. 초안을 어디까지 보여줄지 결정한다

- [ ] GitHub 저장소의 공개 범위를 확인한다. 현재 `imjinfive/factner`는 공개다. 코드도 비공개로 둘 계획이면 비공개 원격을 준비한 뒤 푸시한다.
- [ ] 로컬에서 가상의 이름·연락처·테스트 서류로 가입한다. 운영 데이터베이스와 실제 사업자등록증은 테스트에 사용하지 않는다.
- [ ] 서버에서 함께 검토할 때는 초대한 이메일만 미리보기에 접속하게 한다. 로그아웃한 브라우저에서 기본 도메인, www 주소, API 직접 주소까지 접근이 거부되는지 확인한다.
- [ ] 운영 비밀키, 관리자 비밀번호, 회원 자료, 데이터베이스 백업이 커밋과 배포 파일에 없는지 확인한다.

## 2. 실제 회원 정보를 받기 전에 준비한다

- [ ] 공개할 운영 상호와 실제로 답변할 문의 이메일을 정한다. 담당자에게 문의 한 건을 보내 수신을 확인한다.
- [ ] 가입 유형별 필수·선택 항목을 정한다. 담당자 연락처, 사업자등록증, 현장 사진 각각에 대해 수집 목적과 필요한 최소 범위를 확인한다.
- [ ] 승인·반려·탈퇴 후 자료별 보유 기간, 삭제 방법, 백업 보존 기간을 정한다. 열람·정정·삭제 요청을 처리할 담당자와 연락처를 안내한다.
- [ ] 개인정보처리방침과 수집·이용 안내를 실제 처리 방식에 맞춰 게시한다. 동의로 수집하는 항목은 목적·항목·보유 기간·거부권과 거부 시 불이익을 가입 전에 알린다.
- [ ] 서버·보안 서비스의 수탁자와 처리 지역을 확인한다. 국외 이전이 있거나 거래 연결 후 상대방에게 연락처를 제공한다면 각각의 근거와 안내 절차를 확인한다.
- [ ] 실제 제공하는 서비스를 기준으로 이용약관을 게시한다. 가입 심사와 거래 연결을 구분하고, 고객 화면에서 최신 약관과 처리방침을 열 수 있는지 확인한다.

## 3. 가입과 권한을 검증한다

- [ ] 브랜드와 패키징 제작업체 각각에서 개인·개인사업자·법인사업자로 신청한다. 사업자 증빙, 제출 전 확인, 신청 완료, 관리자 심사 대기를 확인한다.
- [ ] 승인 전 로그인이 거절되고 승인 후 허용되는지 확인한다. 디자이너는 화면과 직접 API 요청 모두에서 신규 가입이 거절돼야 한다.
- [ ] 필수 동의를 빼거나 이전 약관 버전을 보내면 신청이 거절되는지 확인한다. 운영 도메인의 스팸 방지 검증도 통과·실패 양쪽을 시험한다.
- [ ] 일반 회원·비회원이 다른 신청자의 이메일, 증빙 파일, 비공개 공고를 열 수 없는지 확인한다. 모바일에서 가입과 뒤로가기를 한 번씩 실행한다.

## 4. 실제 접수는 마지막에 연다

- [ ] 배포 대상과 데이터베이스를 확인한다. 백업과 복구 절차를 점검하고, 문제가 생기면 접수를 닫을 담당자를 정한다.
- [ ] 고객 Worker의 `DRAFT_SIGNUP_ENABLED`를 끄고 배포한다. 테스트 계정과 실회원의 데이터를 분리하고 테스트 가입 안내가 사라졌는지 확인한다.
- [ ] 대표 관리자 **설정 → 운영 문서 → 회원가입 접수 설정**에서 상호와 문의 이메일을 저장한다. **운영 문서**에서 확정본을 게시한 뒤 접수 설정으로 돌아와 회원가입만 연다.
- [ ] 공개 화면에서 실제 접수 가능 상태와 승인 대기열을 확인한다. 운영 DB에 테스트 회원이나 허위 서류를 넣지 않는다.
- [ ] 접수를 중지해야 하면 같은 화면에서 회원가입 접수를 끈다. 운영 문서 변경 뒤에도 접수가 다시 닫히므로 새 버전을 확인한 후 연다.
