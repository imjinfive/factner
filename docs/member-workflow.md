# 회원·업체 관리와 검토 흐름

2026-10-28 사용자 요청 반영. 가입 전에는 명확히 예시로 표시한 후보를 미리 보고 가입을 신청한다. 승인 회원에게는 실제 등록 후보만 표시한다.

## 운영 순서

1. 회원 가입 신청을 심사해 승인한다. 가입 대기 회원은 회원 기능을 이용할 수 없지만, 올바른 로그인 정보로 심사 상태와 등록된 담당자 안내를 확인할 수 있다.
2. **회원·업체 관리 → 회원 이름 → 업체 상세 입력**에서 소개, 품목, 수량, 생산 희망 기간, 납품 조건 등을 입력한다. 확인된 내용만 입력하고 후보 표시를 켠다. 연락처·상호·내부 기록은 후보 응답에 포함하지 않는다.
3. 브랜드의 패키징 사진·사양은 같은 회원 상세의 **패키징·사진 관리**에서 등록한다. 브랜드가 직접 추가·수정한 경우 검토 대기 요청이 생성된다. 승인 전에는 기존 사양을 덮어쓰지 않는다.
4. 로그인한 브랜드는 제작 업체를, 제작 업체는 브랜드를 품목별로 검색하고 여러 후보를 선택한다. 지역 입력과 문구는 없으며 실제 후보가 없으면 운영팀에 조건을 전달한다.
5. 관리자 **파트너 선택 요청**에서 요청자와 대상자를 확인한다. 실제 거래 조건을 양측과 확인한 뒤 **거래 연결**하면 양방향의 관련 선택 요청을 함께 완료한다. 처리 완료라는 기록만으로 거래를 생성하지 않는다.
6. 새 발주는 활성 거래 관계와 승인된 자기 계정의 패키징이 있어야 한다. 요청 시 승인 사양 버전을 확인하고 스냅샷으로 보관한다. 수량·납기·배송지와 자료 전달 동의를 다시 확인한다.

## 기존 자료

- 회원·기존 발주·파일을 삭제하지 않는다. `0011_member_workflow.sql`은 업체 프로필, 선택 요청, 사양 검토 기록과 발주 사양 참조를 추가한다.
- 기존 패키징은 자동으로 검증된 것으로 간주하지 않고 검토 대기로 옮긴다. 기존 발주 스냅샷은 바꾸지 않는다.
- 회원 계정과 무관한 예전 업체 자료는 회원·업체 관리 하단의 별도 보관 링크로 접근한다.
- 거래 연결이 없더라도 과거 발주가 있으면 발주 내역 탭을 유지한다. 새 발주만 이용 가능한 연결과 승인 사양이 있을 때 허용한다.

## 담당자와 회원 요청

- **회원·업체 관리 → 회원 이름 → 담당자·처리 시간**에서 담당자 이름·전화·이메일과 가입·패키징·매칭·문의 예상 시간을 저장한다. 마이페이지에 반영되며 없는 정보는 배정/확인 대기로 표시한다.
- 회원은 **내 정보 → 우리 업체 정보 / 회원정보 수정 요청** 또는 담당자 문의를 이용한다. 기존 승인 데이터는 바로 바뀌지 않는다.
- 관리자는 회원 상세 위쪽 요청 목록에서 접수 → 검토 중 → 완료/보류로 처리한다. 정보 수정은 실제 회원·업체 양식에 저장한 뒤 반영 확인을 선택하고 완료한다. 고객에게 보이는 처리 안내를 반드시 남긴다.
- 저장·재조회 중 전체 편집을 잠그고 다른 양식의 미저장 내용과 선택 파일을 유지한다. 충돌하면 **입력 유지하고 최신 내용 불러오기**로 최신 값과 초안을 비교한 뒤 다시 확인·저장한다.
- 큰 참고 사진은 최대 30MB 입력에서 1.5MB 이하로 압축한다. 인쇄용 원본을 보관하고, 1.5MB 초과 PDF는 별도 전달 경로를 담당자와 확인한다.

## 확인 화면과 알림

주요 제출·수정은 입력 내용을 표시하는 확인 창을 거친다. 비밀번호와 복구 코드는 확인 요약에 표시하지 않는다. 계정 복구는 기존 본인 확인·단일 사용 코드 방식을 유지한다.

관리자 상단과 메뉴에 비밀번호 복구·후보 선택·사양 검토·회원정보 수정/문의 건수가 표시된다. 접수와 검토 중은 모두 미완료에 포함하며 완료 내역은 접어서 표시한다. 20초마다 갱신하며 실패 시 마지막 건수와 갱신 오류를 표시한다. 문서·이메일 알림 발송과는 별개이며 외부 메시지는 자동으로 보내지 않는다.

대표 관리자 로그인 첫 화면은 회원·업체 관리이며, 일반 관리자는 발주 관리로 진입한다.
